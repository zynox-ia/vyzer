# Design system package, documented inside the app

The interface lives in `packages/design-system` (`@vyzer/design-system`): tokens, global styles, icons and components, consumed by `apps/web` and future products. It is documented in the app itself, at `/design-system` (`apps/web/src/features/design-system`), not in Storybook: one URL per item, a top bar with the sections (Foundations, Visual assets, Components, Forms, Navigation, Feedback, Data Display, AI, App Shell, Data Visualization, Patterns, QA), a sidebar with the items of the active section, and a fixed toolbar for theme and focus variant. Every component page follows one template: when to use, playground, showcase, states, both themes, anatomy and guidelines, usage and props, and the decisions with the rule behind each one. The route exists only in development for now; later it will be restricted to Admins.

The design system is the visual source of truth for product screens. The `vyzer-ui-design` skill (`.claude/skills/vyzer-ui-design/SKILL.md`) is used only to build or change the design system, and every decision cites its rule. ADRs take precedence over the skill.

Tokens have three layers: primitives (raw palette, CSS only), semantic tokens per theme (the only utilities components use) and component tokens when needed. Tailwind's default scales are removed.

## Consequences

- Storybook is not used; the Phase 1 attempt with Storybook is archived at tag `archive/design-system-storybook-v1`.
- The documentation is the first client of the design system: as components are ready, the `/design-system` area is rebuilt with them.
- A screen that needs something the design system lacks proposes the addition first; it does not improvise locally.
